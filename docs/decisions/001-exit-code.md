# 001：子プロセスの終了コードを呼び出し元へ伝える

記録日：2026年10月28日

## 目的と選択

エージェントをシェルスクリプトから使うときに、実行したジョブの結果を終了コードで判断できるようにする。

比較したのは、子の通常の終了コードをそのまま返す方式と、子の失敗を一律1にする方式。前者は子が返した詳しい値を残せる。後者は成功・失敗だけを判定する使い方に単純化できるが、元の値の違いが失われる。

AIの比較説明と代表的なCLIの仕様の紹介を受け、本人は前者に同意した。まずは、終了コードが取得できる場合の引き継ぎを実装した。

参考：[GNU env](https://www.gnu.org/s/coreutils/manual/html_node/env-invocation.html)、[GNU timeout](https://www.gnu.org/software/coreutils/manual/html_node/timeout-invocation.html)。これらは独自のエラー条件を除き、実行したコマンドの終了コードを返す。

## 観測したこと

環境はMacのarm64、およびAzureのUbuntu 24.04.5 LTS / aarch64。Rust/Cargoは両方1.96.0。Macのバージョンは本人の出力、UbuntuのバージョンはAIのSSH照会で確認した。以下の4ケースは両OSで本人が実行結果を提示し、AIが記録したもの。

- 変更前：子の `false` の終了コードを `Some(1)` と表示しても、エージェント自身はシェルへ0を返した。
- 書き方の確認用に固定7を返す版では、子の表示が `Some(1)` でもシェルは7を受け取った。
- 子の終了コードを返す版では、次の確認を行った。

```bash
cargo build

./target/debug/linux-job-agent /bin/echo hello world
echo $?
# 本人の出力：hello world、その後0

./target/debug/linux-job-agent /usr/bin/false
echo $?
# 本人の出力：1

./target/debug/linux-job-agent /bin/sh -c 'exit 7'
echo $?
# 本人の出力：7

./target/debug/linux-job-agent /no/such/command
echo $?
# 本人の出力：No such file or directory (os error 2)、その後1
```

最後の版は、通常の終了コードを保ったまま親が返せることと、起動失敗時にも非ゼロを返すことを、上記の範囲で確認できた。本人は、入力するコマンドに応じて異なる終了コードを返すことを確認する、と説明した。AIは、1だけでは失敗を一律1にする実装と区別できないため7も試した、と補足した。

## 現在の制約

- 終了コードがない場合は `ExitCode::FAILURE` を返す実装であり、シグナルによる終了の情報は呼び出し元へ再現しない。この経路の実行は未確認。
- 起動・終了待ちのエラー、およびコマンド未指定も、現時点では共通の失敗コードを返す。現在版のコマンド未指定の実行は未確認。
- 起動失敗と、子が終了コード1を返した場合は、終了コードだけでは区別できない。起動失敗にはメッセージを表示している。
- エラーメッセージは現在stdoutへ表示している。
- `code as u8` は今回のMac/Linuxの通常の終了コードの範囲を前提としており、全OSでの任意の終了状態を完全に再現する設計ではない。

起動失敗の細分化、シグナル終了の扱い、標準エラー出力への診断の分離は、今後必要な段階で設計する。
